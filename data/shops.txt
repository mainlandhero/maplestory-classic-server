# NPC shops - Victoria Island and Ossyria, complete as of 2026-08-19
#
# AUTHORED DATA, NOT GENERATED. This file is the one place in the repo that holds game
# content we wrote down rather than extracted, and it is deliberately NOT in gm-handbook/ -
# that directory is generated, gitignored and never hand-edited. This is the opposite: it is
# source, it is committed, and nothing regenerates it.
#
# Gathered by the owner from the live game, 2026-08-19, and every shop is labelled "COT2 prices"
# there. It is the only source for these numbers: shop contents are NOT in the client's WZ -
# see STATUS.md goal F, where that was checked three ways with a control each.
#
# ## Prices
#
# The number here is the BUY price - what the NPC charges.
#
# The SELL price is a different thing and comes from the client: `Item.wz <id>/info/price`.
# The owner, 2026-08-19: "The prices client side most likely represents sell prices."
# The evidence beside that reading: every consumable checked is exactly 10.00x its WZ price
# (Red Potion 5 -> 50, Blue Potion 22 -> 220, Meat 8 -> 80, Lemon 15 -> 150 - nine of nine),
# but Pet Food is 15 -> 35, so the ratio is NOT a constant and buy prices cannot be derived.
# They have to be authored, which is what this file is for.
#
# ## Format
#
#   shop: <npc name> | <role> | <map>
#   <tab><item name>[ (M)|(F)]<tab><price>[<tab>rank]
#
# Item NAMES, not ids, on purpose: the ids come from the client's own String.wz name table
# (`gm-handbook/items.txt`), so a name that does not resolve is a transcription error this
# file can be checked for rather than a wrong item shipped silently.
#
# ## The (M) / (F) tag
#
# A trailing `(M)` or `(F)` is part of the format, not decoration, and it is NOT stripped
# before the name is looked up - it SELECTS between two ids sharing one name. MapleStory
# equips encode gender in the id itself, `(id / 1000) % 10`: 0 male, 1 female, 2+ unisex.
# Sam sells `Green Bennis Chainmail (M)` at 1040033 and `Green Bennis Chainmail (F)` at
# 1041040, and without the tag those two rows are indistinguishable.
#
# That convention is measured here, not taken from the family's usual shape: of the 97 tagged
# rows in this file, **90 were transcribed off the live UI by the owner** and there are ZERO whose
# tag disagrees with the gender their id implies. The client agrees from the other side too -
# its own String.wz ships one item name with the suffix baked into the name itself,
# `Natalie's Fashion Box (M)` / `(F)` at 2430001 / 2430002.
#
# The remaining 7 tags were added here rather than transcribed; each is marked at its row.
#
# What is NOT established is *when* the live UI adds the suffix. It is not "the item is
# gender-locked" - `Green Hunter's Pants` is male-only (1060034) and untagged, while
# `Archer Pants (M)` is unisex (1062000) and tagged - and it is not "two rows in this shop
# share a name" either, since `Green Archer Top (M)` has no female twin. A tag is therefore
# read as a HINT that narrows, never as an assertion about the item, which is why a tag on an
# unambiguous name is accepted and ignored rather than checked.
#
# A tag on an item whose name is unique is harmless and is left as transcribed.
#
# ## rank - citizenship grade
#
# `rank` is the citizenship gate shown in the live UI ("Town Resident+"). The tag is a grade
# NAME and `+` means that grade or higher, so every gated row is an integer comparison:
#
#    1 Traveler          3 Helpful Stranger    5 Town Resident   7 Distinguished Citizen
#    2 Visitor           4 Recognized Guest    6 Trusted Neighbor  8 Town Patron
#    9 Guardian of the Village                10 Citizen of Honor
#
# The system is the client's own: all 88 citizenship quests are in `Quest.wz` (506000-506141,
# count matches exactly), and `citizenshipGrade` / `citizenshipTown` are real Check keys with
# 86 uses each. The grade NAMES are corroborated by being exactly the tags in this file. The
# grade-to-character-level mapping (Traveler 12, Visitor 17, ... Citizen of Honor 57) is [I]
# from a fan site - see STATUS.md goal H for the full working.
#
# Items with a rank must not be sold to a character below that grade. The prices below are
# the UNDISCOUNTED list prices as shown in the live UI; citizenship discounts are goal H's
# business and are applied on top, not baked in here.
#
# ## Corrections applied 2026-08-19 - spelling only, never a price
#
# Every name in this file was resolved against the client's own name table. 121 rows did not
# resolve, in three systematic classes, and each was corrected to the client's spelling. The
# transcription was right about the item every time; it differed only in punctuation and
# number. The owner's original wording, where it is not obvious from the correction:
#
#     Red-Striped top          -> Red Striped Top          (hyphen; the client uses a space)
#     Red-Striped T-Shirt (F)  -> Red Striped T-Shirt (F)
#     Subi Throwing-Star(s)    -> Subi Throwing Stars      (hyphen, and always plural)
#     Blue Jeans Shorts        -> Blue Jean Shorts         (the client's is singular "Jean")
#     Arrow for Bow            -> Arrows for Bows          (the client pluralises both nouns)
#     Arrow for Crossbow       -> Arrows for Crossbows
#     <colour> Pao Bottom      -> <colour> Pao Bottoms     (plural)
#
# Seven further rows named an item that exists twice, once per gender, and carried no tag.
# They are tagged `(M)` below, derived from position - see the comment at each one and
# `research/shops.md`. NO PRICE IN THIS FILE HAS BEEN CHANGED.
